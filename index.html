GitHubsquared-netizen

squared-netizen builds squared, a C++23 framework for Linux and Android, and the tools around it: a project generator, a container format for its templates and packages, and sqterm, a terminal for Android written on it. Everything is built and tested on a phone. A clean checkout and the vendored sources build offline; the network is a deliberate step of its own, never part of a build.

Planned projects

ProjectKindIdea
ManualsCommand-line appA command-line app for storing and managing documentation: man pages, squared's manuals and notes, listed and searched, and filtered to the tools actually installed. Built to be embedded later in an IDE or a game engine, not as a separate app.
sqmakeBuild system (library and command-line tool)A build tool that runs the build itself, with no generated make, CMake or Ninja files: make's model (targets, prerequisites, rebuild when inputs change) with Ninja's engine (command hashes and compiler-written header dependencies), Cargo's conventions and short manifest, Lua 5.4 as the escape hatch, and CMake's usage requirements. A standalone library, libsqmake, with a thin sqmake command line, like sqcart: squared-pg embeds it for its build step, and it knows nothing about squared-pg. It owns its Lua state when run alone and uses its host's when embedded. Offline, no daemon, commands as argument lists, C++23 modules as its interface, and --explain to show the whole resolved graph.
Virtual Cartridge Drive (sqcart 3.0)Storage layerA mutable, disk-backed view over .sq cartridges. Reads resolve against staged changes and the mounted cartridge; writes are buffered on disk, coalesced, and committed through sqcart's format-aware operations at chosen times (on request, at a pause, at a size or time budget, at shutdown). sqcart stays the authority on what a valid cartridge is; the drive decides how to work with one efficiently, in bounded memory.
apkpackBuild toolA native replacement for aapt2, zipalign, apksigner and android.jar: an APK built and signed with no Java and no Android SDK.

Workflow

Work runs as sprints of small tasks. Each task is a pull request: a branch is pushed, GitHub Actions builds and checks it, fixes follow until it is green, and a merge closes the task. The sprint tracker reads that history live from GitHub: what is in progress, what is blocked on a red check, what is ready, and what each sprint finished.
