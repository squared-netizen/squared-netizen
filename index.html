squared-netizen builds squared, a C++23 framework for Linux and Android, and the tools around it: a project generator, a container format for its templates and packages, and sqterm, a terminal for Android written on it. Everything is built and tested on a phone. A clean checkout and the vendored sources build offline; the network is a deliberate step of its own, never part of a build.

The squared SDK

The squared SDK is a framework, the tools that create, manage and build what is written on it, and the command-line environment they run in. The names follow one rule: squared is the framework, square is the manager, and squared-name are the framework's add-on packages.

The framework

squared-core is what every application is written against. Add-on packages extend it in one field each, and are expected to be substantial; what all or nearly all of them share moves into core. They are built only when something needs one, or when code added to core grows too large or plainly belongs in one, so for now they wait.

The tools

Every tool learns what a workspace is from the cartridge specification. sqcart is its lowest-level user and knows nothing of workspaces; square is the one tool that does, and the others ask square.
  • sqcart reads and writes cartridges (.sq): the specification's reference implementation.
  • square manages workspaces. A manifest question goes to square, which asks sqcart and answers in JSON, so no other tool reads cartridge manifests itself and a change in sqcart touches square alone. It can also turn a workspace that has grown to suit its developer into a template, kits and packages for the next project.
  • sqpg creates: it sets up a workspace tree and generates a project from the template, kits and packages it is given.
  • sqmake builds an application from a workspace, knowing how to build it rather than what a workspace is.
  • sqgui edits an application's UI visually, through the JSON layout files squared already reads; it takes in sqgen, which compiles them.

The workflow

  1. Create a workspace with sqpg.
  2. Manage it with square, and with sqgui for its user interface.
  3. Build the application from it with sqmake.

Around them, the environment the work happens in: zsh, the whole clang toolchain, neovim and sqedit, run on the phone in sqterm or Termux.

Workflow

Work runs as sprints of small tasks. Each task is a pull request: a branch is pushed, GitHub Actions builds and checks it, fixes follow until it is green, and a merge closes the task. The sprint tracker reads that history live from GitHub: what is in progress, what is blocked on a red check, what is ready, and what each sprint finished.
