apkpack

Builds and signs Android APKs with no Java, no Android SDK and no SDK licence: one native C++ tool for the squared SDK in place of keytool, apksigner, aapt2, zipalign and android.jar.

Status: planned, not yet built.

What it will be

One program with subcommands, so the build can move to it a step at a time:

CommandReplacesDoes
apkpack keygenkeytoolan ECDSA P-256 key and a self-signed certificate; an existing debug key can be imported
apkpack sign, apkpack verifyapksignerAPK Signature Scheme v2 (Android 7.0 and later)
apkpack addzip, zipalignlib/ and classes.dex, stored entries aligned (4 bytes, 16 KB for a stored .so)
apkpack linkaapt2, android.jarthe manifest and XML resources as binary XML, resources.arsc, assets
apkpack dumpaapt2 dumpthe binary manifest as text
apkpack explainnonewhat a dex shim does, its bytecode and spec references, as JSON

The framework attribute IDs android.jar supplied come from AOSP's public tables (Apache-2.0), pinned as a source. Dex code is never compiled here: dexgen writes squared's shims, and apkpack packs them.

The plan

  1. Sign: keygen, sign, verify. The build no longer needs Java.
  2. Package: the zip writer with alignment.
  3. Link: binary XML, resources.arsc, the attribute table. No aapt2 or android.jar.
  4. Switch: squared's template calls apkpack. No SDK at all.

Each phase is checked against the tool it replaces, and on the phone by installing and launching the APK.
