app

The platform-neutral boundary. The platform adapter owns process setup, the event pump and the soft keyboard, and drives an Application. Nothing above this layer names SDL or Android.

An app does not implement Application any more (Sprint 7.1): sq::App does, and an app writes squared_main and its model (stage.md). This page is for a platform layer, and for a program that wants the bare boundary without the App.

Developer counterpart: ../developer/app.md

Aggregate headers

squared/app/application.cppm is both the Application interface and the module's aggregate header: it pulls in Event and the text-input types, because implementing Application needs all of them. squared/app/src/text_input.cppm aggregates the four text-input types.

Keys, modifiers and navigation

There is one of each in squared, and the GUI uses the same ones: what the platform puts in an Event is exactly what a widget's key_down receives.

import sq.app;

if (event.type == sq::app::Event::Type::KeyDown &&
    event.key == sq::app::Key::enter && event.modifiers.control) {
    submit();
}

sq::app::KeyModifiers held{.shift = true};   // build one with designated initializers
if (held.any()) { /* ... */ }

Key names the keys that do something rather than type: the arrows, Home and End, Backspace and Delete, Enter, Space, Tab, Escape, and from 12.3d the ones a terminal needs, page_up, page_down, insert, f1 to f12. What a key types (letters, digits, punctuation) comes as TextInput text; with Ctrl, Alt or Meta held, as the character without them plus those modifiers in event.modifiers (Ctrl-C is "c" with control), which the GUI gives to Widget::key_text instead of text_input. A key that types something else with them held (AltGr's @ on a German keyboard) comes as plain text.

TypeValues
Keyunknown, left, right, up, down, home, end, backspace, delete_key, enter, space, tab, escape. A key squared doesn't name arrives as unknown, with the platform's code in Event::input_device_id

Implementing an Application

import sq.app;

class MyGame final : public sq::app::Application {
public:
    bool create(sq::graphics::Context& graphics) override;
    void handle_event(const sq::app::Event& event) override;
    void update(std::chrono::nanoseconds delta) override;
    void render(sq::graphics::Context& graphics) override;
    void dispose() override;
    [[nodiscard]] bool quit_requested() const noexcept override
    {
        return quit_;
    }

private:
    bool quit_{false};
};

create, handle_event, update, render, dispose and quit_requested are required. pause, resume, resize, surface_created, surface_destroyed, set_text_input_service, set_clipboard_service, set_background_service, set_report, foreground, background, low_memory, set_saved_state, save_state, take_background_request and hides_bars have empty defaults, so a desktop-only application can ignore them &mdash; but on Android surface_destroyed and surface_created are where GPU resources are invalidated and restored, and ignoring them is a bug that only shows on device.

CallWhen the platform makes it
set_report(report)before create(): report(line) says something went wrong (Android: the system log, and the Console when built in)
set_background_service(service)before create(): the platform's way to keep running off the screen (BackgroundService, below), the same one for the whole process
set_clipboard_service(service)after create(): the system clipboard (ClipboardService, below), or nullptr where the platform has none; nullptr again in dispose() (sq::App clears its Stage's)
foreground()the app is visible again (Android's start); not before the first create()
background()the app is no longer visible (Android's stop): it may never come back, so state is made safe here
low_memory()the system is short of memory
set_saved_state(bytes)before each create(): what Android kept for the activity (its saved instance state), valid until create() returns. Empty for a new launch: after a swipe from the recent apps, a finish, a force stop or a reboot; Android keeps it only when it ended the process itself or made the activity again
save_state(out)Android asks what to keep with the activity: write at most Application::saved_state_bytes (8 KB) into out, and return how many; 0 for nothing
take_background_request()each loop turn: true, once, when the application asked to go to the background (sq::App: back at its root screen); the platform moves its task back, as Home does
hides_bars()each frame: whether the status and navigation bars should be hidden (immersive); the platform hides or shows them when the answer changes, and again after each focus

Feeding the GUI

sq::App is the Application an app uses: it hands each event to its Stage, which routes it to the widgets, and gives the TextInputService* it receives to them, so a focused text field raises the soft keyboard. The widgets' host it uses (gui::Ui) is internal since 7.7. The ClipboardService* it receives goes to its Stage, where a widget reaches it (stage.clipboard(), stage.md).

The clipboard

sq::app::ClipboardService (squared/app/src/clipboard_service.cppm) is the system clipboard's text, implemented by the platform (Android: the template's sq_android::Clipboard, ClipboardManager through JNI). Called on the application thread.

MemberDoes
text(out)the clipboard's text as UTF-8 into out: whole characters, in order, until one does not fit. Returns the bytes the whole text takes, whatever out holds; 0 when it holds no text
set_text(utf8)the clipboard holds utf8 now; false when the platform refused
if( sq::app::ClipboardService *clipboard = stage.clipboard() ) {
    std::string text( clipboard->text( {} ), '\0' ); // the size
    clipboard->text( text );                          // then the text
    clipboard->set_text( "copied" );
}

Failure modes: nullptr for no clipboard (a host build, a platform without one); 0 from text for no text; false from set_text. Not bound to Lua.

Running in the background

sq::app::BackgroundService (squared/app/src/background_service.cppm) keeps the process running with the app off the screen (Android: the template's sq_android::Background, a foreground service with a notification). An app using sq::App calls app.keep_running(...) (stage.md); this is the platform's side.

MemberDoes
available()the app declared it and the platform can do it (Android: BACKGROUND=1)
keep_running(title, text)keep running, the notification titled title saying text (each at most 63 bytes); again to change the text; false when not available
stop_running()stop: the notification goes, and the wake lock; idempotent

Exit in the notification reaches the application as Event::Type::QuitRequested.

The safe area

Android draws the application edge to edge, so the status bar, the navigation bar and a camera cut-out sit on top of it. The platform layer measures how far they reach and tells you:

void MyGame::safe_area_changed(const sq::app::SafeArea& area)
{
    // pixels: area.left, area.top, area.right, area.bottom
    // (sq::App passes it to its Stage, which keeps screens and panes inside it)
}
TypeHeaderPurpose
SafeAreasquared/app/safe_area.cppmFour 16-bit pixel counts: how far something covers each edge of the drawable

safe_area_changed() is optional (the default ignores it) and is called after create() once the bars are known, then whenever they change &mdash; rotation, the bars hidden or shown (they are hidden by default: hides_bars()), the keyboard. On Android it is measured on those events only, never on a timer (since 7.8; it was twice a second). The first call can come a fraction of a second after the first frame, because Android has not laid the window out before then. A platform with nothing covering the window never calls it.

Values are in drawable pixels, like resize(). Convert to your logical unit the same way you convert pointer positions.

Lua: not bound.

The runtime

create() receives a sq::app::Runtime &mdash; the three services only the platform layer can build:

bool MyGame::create(sq::app::Runtime& runtime)
{
    graphics_ = &runtime.graphics;
    files_    = &runtime.files;
    assets_   = &runtime.assets;

    auto atlas = runtime.files.internal("skins/default/skin/uiskin.atlas");
    return atlas.exists();
}
MemberWhat it is
graphicsthe rendering context; survives surface loss
filesstorage: internal is the read-only APK bundle, local is private writable storage, external is shared
assetsthe typed asset cache, reading through files

Keep references to what you use. Every member refers to an object that lives for the whole process.

Only create() gets the runtime. render() still takes the context alone, because a frame should not be reaching into the file system or the asset cache sixty times a second.

On Android, the storage names cross

squaredAndroid calls it
internalthe APK's assets/read-only, ships with the app
localinternal storagewritable, private, no permission, gone on uninstall
externalexternal storagemay be unmounted, so may be empty

Save games, settings and caches go in local. It needs no permission and is removed with the app.
