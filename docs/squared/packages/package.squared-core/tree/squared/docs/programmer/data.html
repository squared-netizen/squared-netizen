data

Strict RFC 8259 JSON: an owned value type independent of the parser backend, plus one parse function and one write function. Used by the skin loader, and for saves and layouts.

Free functions

squared/data/json.cppm is the module's aggregate header and also declares:

FunctionPurpose
parse_json(std::string_view, const JsonParseOptions&)parse exactly one strict JSON document
write_json(const JsonValue&, const JsonWriteOptions&)serialize with stable key ordering

Both are noexcept and report failure through the returned result, so this module already follows the framework's no-exceptions rule.

I-JSON, and the canonical form

Two options for JSON that is hashed, signed or exchanged between programs that must agree on it (sqcart's 3.0 cartridges, for one):

  • JsonParseOptions::ijson: accept only I-JSON (RFC 7493). Duplicate keys, invalid UTF-8 and lone surrogates are refused anyway; this also refuses an integer beyond ±(2^53 − 1), which a double cannot hold exactly (JsonErrorCode::IntegerOutOfRange). Write such a number as a string.
  • JsonWriteOptions::canonical: write the canonical form of RFC 8785 (JSON Canonicalization Scheme): members ordered by their names' UTF-16 code units, numbers as ECMAScript writes them (1e+21, 0.000001, 5e-324), the fewest escapes, no whitespace. The same value always gives the same bytes. pretty and newline_at_end are ignored, and an integer beyond ±(2^53 − 1) is an error.
const auto parsed = sq::data::parse_json(text, {.ijson = true});
const auto canonical = sq::data::write_json(parsed.value, {.canonical = true});

Reading a value

Accessors return a pointer that is null when the value holds a different type, so there is no throwing alternative to guard against:

const auto result = sq::data::parse_json(text);
if (!result.error.ok()) return;

if (const auto* object = result.value.object_if()) {
    if (const auto* name = object->find("name")->string_if()) {
        use(*name);
    }
}

yyjson

parse_json and write_json are implemented over yyjson, but nothing in the public API exposes it: JsonValue owns its own storage and outlives the parse. Only data/src/json.cpp includes yyjson.h.
