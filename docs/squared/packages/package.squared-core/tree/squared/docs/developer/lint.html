Lint

How sqmake lint (tools/lint.sh) works, what it checks, and why each check is there.

Programmer side: none. Lint checks the framework's own source; a project's code in sq_app/ and sq_android/ is the project's business. Related: code-style.md (the format rules), tools.md (the script), priority-audit.md (the findings the rules track).

Three layers

layercatchestoolstatus
1. clang-tidyowning raw pointers, missing special members, copies, oversized enums, bugssquared/.clang-tidyin sqmake lint
2. source ruleswhat clang-tidy has no check for: std::function, exceptions, RTTI, any new/deletetools/lint-rules.txt and tools/lint-baseline.txtin sqmake lint
3. frame-allocation countera heap allocation inside the frame loopthe dev module, in DEV_LOG buildsreports on the device

No static check can prove the frame loop does not allocate: a std::vector::push_back is fine at load time and a bug at frame time, and the code is the same. Layers 1 and 2 keep ownership honest; layer 3 measures the loop.

A format check runs first, so sqmake lint is the one command for all of it.

Running it

sqmake lint                            # everything, every file
tools/lint.sh --changed                # files changed since the last commit
tools/lint.sh --since HEAD~1           # files the last commit touched
tools/lint.sh --only tidy              # one step: format, rules or tidy
tools/lint.sh gui/src/ui.cpp           # the files named
tools/lint.sh --jobs 2                 # fewer clang-tidy processes at once
tools/lint.sh --record-baseline        # accept today's rule matches

Progress prints as it goes: a line per 40 files for the format step, a line per rule, a line per translation unit for clang-tidy. The report is build/lint/report.txt; clang-tidy's full output, with its notes and fix-it hints, is in build/lint/tidy/<file>.log.

exitmeaning
0no findings
1findings; the report lists them
2usage error, a named file that does not exist, --changed or --since outside git, an unknown commit for --since, --record-baseline with a file list

A step whose tool is missing says so and is skipped. It does not fail the run: a machine without clang-tidy can still run the rules.

Engine and data

build.lua holds one action for lint: bash tools/lint.sh. Everything else is in two kinds of file:

  • the engine, tools/lint.sh: finds files, runs tools, compares with the baseline, prints progress, writes the report.
  • the data: .clang-tidy (which checks) and tools/lint-rules.txt (which patterns), plus tools/lint-baseline.txt (which matches are accepted).

The split is there so the engine can be replaced (in Lua, with PEG matching instead of regular expressions, say) without touching the build or the rules. A replacement must keep:

  • the command line above;
  • the rules format (below) and the baseline format, rule file count, one per line, # starting a comment or a reason;
  • the report path and the exit statuses;
  • the stripping contract for rules: a pattern is matched against code with comments removed and string and character literal contents blanked, line for line.

A PEG engine can read match as it likes, but the five rules today are written as POSIX extended regular expressions plus \b, which GNU grep (what Termux ships) and BusyBox grep both accept with -E.

Layer 1: clang-tidy

squared/.clang-tidy enables checks by group. Each group serves a priority:

groupcheckspriority
ownershipcppcoreguidelines-owning-memory, -no-malloc, modernize-make-unique, -make-shared1: memory is owned by a type that frees it
class hygienecppcoreguidelines-special-member-functions, -slicing, -virtual-class-destructor, -rvalue-reference-param-not-moved, -missing-std-forward1: no accidental copies, no leaks through a base pointer
size and copiesperformance-*, including performance-enum-size1, then 3
bugsbugprone-* except easily-swappable-parameters (fires on every two-float function) and narrowing-conversions (the build's -Wconversion already reports it); exception-escape ignores three standard-library exception types (triage)correctness
ODR and includesmisc-definitions-in-headers, -header-include-cycle, unused using and alias declarationsthe self-containment invariant
modern spellingnullptr, override, using, = default, = delete, no (void)2
readabilityonly checks that prevent a bug or a slow path2, 3
static analysisclang-analyzer-core, -cplusplus, -deadcode, -unixcorrectness

Not enabled, on purpose: cppcoreguidelines-avoid-magic-numbers, readability-identifier-length, modernize-use-trailing-return-type and the other style checks. They produce volume, not safety, and the style is clang-format's job.

HeaderFilterRegex: '/squared/[a-z]+/' reports findings in squared's own headers and never in third_party/ (the underscore stops [a-z]+) or system headers. The squared-pg repository has its own, broader .clang-tidy at its root; squared/.clang-tidy does not inherit it, so the framework's checks are the same in the package, in an example and in a generated workspace.

What is analysed

Exactly what the build compiles, with the build's own commands: sqmake writes every compile it describes to compile_commands.json in its build folder (sqmake 0.13.0), and clang-tidy reads it (-p). The units are its module sources and interfaces; the tests, the tools, the Console's client and third_party/ are not. -DNDEBUG comes with the commands, and decides which asserts exist. Compiler warnings are left out (--extra-arg=-w): the build already reports those, and clang-tidy would report them again as clang-diagnostic-*.

There are two configurations:

  • host: build.lua (the null backend and the POSIX platform), in build/sqmake/;
  • android: SQUARED_TARGET=android sqmake, the libraries for Android (the gles backend, the Android platform) by the SDK's toolchain, build/toolchain.lua (sqterm's: its sysroot and runtimes), in build/sqmake-android/. It contributes only the sources the host configuration does not compile (gles/, the GLES backend, the Android asset file system). Where that toolchain is not found (a desktop, CI), it is skipped, and says so.

A selected .cpp that neither configuration compiles is named as skipped, never analysed with guessed flags. Each progress line says which configuration a file was analysed in.

Since 7b.4 every module interface (.cppm) is a unit of its own, analysed as the implementation units are; clang-tidy reads the BMIs of what a unit imports, so tools/lint.sh builds first, both configurations (sqmake: quick when the build is current). The few headers left (a test's stub) are analysed through the files that include them; findings are deduplicated by place and check.

A tree without Makefiles (a test fixture) falls back to every <module>/src/**.cpp with -std=c++23 and the layout's include paths.

Versions

Written against clang-tidy 21 (Termux) and checked with 18. The file uses no option either rejects; in particular not ExcludeHeaderFilterRegex, which 18 does not have. Findings can differ slightly between versions: a check gains cases.

Layer 2: source rules

tools/lint-rules.txt holds the rules, one block each:

rule  raw-new
why   no hand-written new: use std::make_unique, a container, or the owning pool (priority 1). ...
match (^|[^_[:alnum:]])new\b[[:space:]]*[(_[:alpha:]:]
files gui/*.cppm gui/src/*     (optional; default: every .hpp, .cpp and .cppm)

The default file set is every .hpp, .cpp and .cppm outside third_party/, build/, docs/ and any test/ directory. Tests may do what the framework may not: files/test/asset_stub.cpp stands in for the NDK's C API, which hands out raw pointers.

rulematcheswhy
std-functionstd::functionheap capture and an indirect call; priority-audit.md item 5
exceptionsthrow, try, catchthe move to -fno-exceptions; items 1 and 3
rttidynamic_cast, typeidthe tree builds with -fno-rtti and has to keep doing so; item 2
raw-newa new expression, placement new includedownership goes through a type
raw-deletea delete expression, not = deletethe same

Matching runs on a stripped copy of each file: comments removed and the contents of string and character literals blanked, line for line, so a match's line number is the source's. A comment that says "do not throw" and the string "try again" do not match. Raw string literals are not understood; squared has none.

The baseline

Code that already breaks a rule is not fixed in one go. tools/lint-baseline.txt records, per rule and file, how many matches are accepted:

exceptions gui/src/ui.cpp 11
std-function gui/widget.cppm 1  # TooltipFactory: side table planned (priority-audit.md item 5)

A file may match a rule as many times as its entry says; a file without an entry may not match at all. The report quotes every matching line of a file over its count, since the engine cannot tell which match is the new one.

After fixing, tools/lint.sh --record-baseline writes the smaller counts; commit that file with the fix. Recording also accepts any increase, and it says so (accepted exceptions gui/src/ui.cpp: 9 -> 11): raising a count is a decision, made in a commit a reviewer sees. A reason written after # on an entry's line survives re-recording. Recording needs the whole tree, so it refuses a file list and --changed.

Heap allocation is not the problem; unowned allocation is

The rules and the ownership checks do not forbid the heap. A texture atlas's pixels are megabytes and belong on the heap. What they forbid is memory nobody owns:

// Rejected: raw-new, and owning-memory (a raw pointer that must be deleted by hand)
auto *pixels = new std::byte[ width * height * 4 ];

// Accepted: the same single allocation, owned; freed by the destructor
auto pixels = std::make_unique_for_overwrite<std::byte[]>( width * height * 4 );

// Accepted: owned and sized, when the size is needed later anyway
std::vector<std::byte> pixels( width * height * 4 );

make_unique_for_overwrite (C++20) skips the zero fill a pixel buffer is about to overwrite: priority 3, at no memory cost. std::vector adds 16 bytes for its size and capacity: acceptable once per resource, not per sprite.

Where allocation happens is a separate rule (load time, not frame time), and layer 3 is what checks it.

A pool that constructs objects in its own storage needs placement new. That is the one legitimate raw-new match: accept it in the baseline with a reason on the entry's line.

Layer 3: the frame-allocation counter

A development build (sqmake --debug in the Android template) replaces the global operator new with one that counts, and the template brackets each frame's update() and render() with sq::dev::frame_begin() and frame_end(). Frames that allocate are reported over the log sink:

alloc: site 1 (frame 3): libdemo.so 0x4a5f0 < libdemo.so 0x51c2c < libdemo.so 0x3e110 < libdemo.so 0x3d9a8
alloc: frame 3: 2 allocations, 96 bytes (the first frame that allocated)
alloc: 41 of the last 120 frames allocated: 82 allocations, 3936 bytes; most in one frame: 2
alloc: by site: 1:41 2:41

Each site is named once, as library offsets; addr2line -f -C -i -e build/libdemo.so <offsets> turns them into functions and lines.

Only the frame thread is counted, and a release build contains none of it. Unlike layers 1 and 2 it does not fail sqmake lint: it runs on the device, so its result is read from nc -klu 5555. How it works: dev.md; how to use it: ../programmer/dev.md.

Memory and cost

None of this is in the application: priority 1 does not apply to it. What it costs is time and the phone's RAM while it runs.

stepprocessesnotes
formatone clang-format per 40 filesabout a second for the tree
rulesone awk to strip every file, one grep per rule, one awk per file over its countunder a second
tidyone sqmake per configuration (quick when built), one clang-tidy per translation unitminutes on a phone

--jobs defaults to the number of CPUs, at most 4. One clang-tidy on a large file can take a few hundred megabytes; four is the most a phone should run next to an editor. Scratch files go to $TMPDIR and are removed on exit.

The engine needs bash 4.3 or newer (wait -n); Termux and current Linux distributions have bash 5. It uses no GNU-only option of find, grep, sed, awk, split or sort.

Known limitations

  • Rules are textual. A new inside a macro defined elsewhere is not seen, and a pattern cannot tell a type from a variable. clang-tidy's ownership checks cover the cases that matter.
  • clang-tidy cannot see a header that no .cpp includes, and a changed header pulls in its direct includers only, not the sources that reach it through another header.
  • The android configuration needs the SDK's toolchain (sqterm's sysroot and runtimes, found by build/toolchain.lua). Without it, the GLES and Android sources are skipped, and the run says so.
  • --changed compares with HEAD: committed work is not re-checked. For that, --since <commit> compares with an earlier commit, so --since HEAD~1 checks what the last commit touched. Both leave out deleted files; until 2026-10-16, --changed stopped with "no such file" on a change that removed a header.
  • clang-format versions disagree on one construct this tree has met: a variable declared with an elaborated type and empty braces, struct sigaction action{};. clang-format 18 reads it as a struct definition and breaks it over two lines; 21, the tree's reference, keeps it whole. Write struct sigaction action = {};, or drop the struct where the name is not also a function's (utsname name{};): both versions leave those alone (found 2026-10-17, when a package formatted with 18 failed the phone's format check)
  • clang-tidy versions disagree at the edges: 21 finds more exception-escape cases (it sees libc++'s throws), 18 finds guarded optionals that 21 does not. The phone's clang-tidy 21 is the reference.

Suppressions

Every suppression names its check and gives the reason on the line above:

// value is in (0, 1) here, so adding 0.5 and truncating rounds half up exactly.
// NOLINTNEXTLINE(bugprone-incorrect-roundings)

NOLINTBEGIN(check) and NOLINTEND(check) bracket a block when one reason covers several lines. A bare NOLINT with no check named is not used.
