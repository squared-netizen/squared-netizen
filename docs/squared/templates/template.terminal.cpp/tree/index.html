Build and run

sqmake        # build: build/{{project_name}}
sqmake run    # build and run
sqmake test   # build and run each sq_app/test/*.cpp

No CMake, no make, no package manager, no network: a compiler and sqmake are the whole dependency list, which is the point of this template: it is meant to work on a phone. sqmake --debug run builds with -O0 -g into build/debug.

Layout

sq_app/        your code — headers in include/, sources in src/
sq_kit/        kit-provided headers (generator-owned)
build.lua      yours: sqmake's build; includes sq/build/template.lua
sq/build/      the template's and each kit's build, in Lua (generator-owned)
SQ-INF/        what this workspace is and was made from (square reads it)

Who owns what

PathOwnerOn update
sq_app/**younever touched
build.lua, README.md, .gitignoreyounever touched
sq_lua/** (with kit.lua)younever touched
sq/build/**, sq_kit/**generatorrewritten
SQ-INF/**generator, then squarerewritten

Every generated path is recorded in SQ-INF/files.json with the hash it had when it was written, so a later update can tell "unchanged since generation" from "the user edited this" without guessing: square verify says which.

You can delete SQ-INF/ and keep a working project. You lose only the ability to update it in place.

Independence

This workspace does not depend on squared-pg. The generator is not on the build path, is not referenced by build.lua, and does not need to be installed to build, run, test or distribute what it produced.

Where to start

sq_app/src/app.cpp. It has a small command loop demonstrating the terminal kit — console I/O, the regex helpers, and FileHandle. Delete what you do not want.
