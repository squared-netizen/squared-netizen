Preferences and the Settings screen

Status: decided (2026-11-25).

Every squared app has settings, and most of them are the same few: the skin, the font (one of the skin's bitmap fonts, or a TTF/OTF file), its size, the colours, whether the keyboard comes up at the start. squared gives them once: a preferences cartridge that holds everything an app keeps, and a Settings screen that shows the invariants and whatever the app adds, with import and export built in. sqterm and sqIDE are the first two users; sqIDE's Settings (docs/design.md there) is this screen.

1. The preferences cartridge

An app's preferences are one squared cartridge (sqcart 3.0), as every workspace is one, and held the same way: exploded while in use, packed only to travel.

<app Local storage>/preferences/
  SQ-INF/manifest.json     kind "preferences", id "preferences.<app id>"
  tree/
    settings.json          the typed settings (below)
    ...                    anything else the app keeps: any file type
  • kind preferences; id preferences. and the app's id (preferences.dev.squared.sqide); version the schema's (below), so an import from an older app can be migrated.
  • settings.json: one JSON object (sq.data), keys dotted by section: ui.skin, ui.font.file, ui.font.size, ui.theme.0 ... ui.theme.19, ui.zoom, ui.zoom.pinch, ui.zoom.least, ui.zoom.most, input.keyboard_on_start, and the app's own (terminal.scrollback). Only what differs from the default is written.
  • Any other file: a TTF the person added (fonts/), a skin of their own (skins/NAME.json with its atlas), a key, a history, an app's own theme.json. The cartridge does not know what they are; the app does.

sq.preferences

A module of squared's, on the UI thread (the model reads a copy it is sent, as a part's argument or a telegram; it never opens the files).

Preferences::open(files, app_id)the cartridge, made with the defaults when it is not there
get<T>(key, fallback), set(key, value), reset(key)a typed setting; set writes settings.json at once (whole, atomically: a new file renamed over the old)
path(name), read(name), write(name, bytes), remove(name)a file of the app's, under tree/
generation()counts changes, as term.theme_generation does: what draws from a setting reads it again when it moves
export_to(file)the cartridge packed into one .sq (sq.drive's pack)
import_from(file, Replace or Merge)a .sq of kind preferences: checked, exploded into a staging folder beside the cartridge, then swapped in (Replace) or its files and keys laid over (Merge)

Import refuses a cartridge of another kind; one of another app's id is offered with a warning (a theme moves between sqterm and sqIDE). A newer schema than the app knows is refused; an older one is migrated by the app's own step (on_migrate(from, settings)).

squared gets the cartridge I/O by vendoring sqdrive (third_party/ sqdrive, as square does): sqcart is the format, sqdrive the I/O, and squared adds only what a preferences cartridge is. The module is not part of import squared; for an app that wants none of it.

2. The Settings screen

sq::SettingsScreen, in squared (sq.stage, drawn with sq.gui): one screen, made from sections, each a list of entries, each bound to one key of the preferences. A change is written at once and published; there is no Save button.

What every app gets

SectionEntries
AppearanceSkin: the app's bundled skins and the ones in tree/skins/ (a skin added brings the bitmap fonts it names)
ZoomZoom: the UI's size, a slider from the least to the most, in the Stage's steps (5%), applied live · Pinch to zoom: on or off · Least and Most: the range a pinch and the slider keep to, within squared's 50% to 300%
TextFont: the skin's bitmap fonts, or a TTF/OTF file (the bundled ones and tree/fonts/, or Add font..., which copies one in) · Size
Coloursthe theme's palette, when the app declares one (16 + 4 for a terminal)
InputKeyboard on start
PreferencesExport..., Import..., Reset all

An app turns any of these off, and adds its own.

An app's own sections

Declared as data, in code or as JSON next to the app's layouts (sqgui's editor can show it later):

{"section": "Terminal", "entries": [
  {"key": "terminal.scrollback", "type": "number", "label": "Scrollback", "min": 100, "max": 100000, "default": 5000},
  {"key": "terminal.bell", "type": "choice", "label": "Bell", "choices": ["off", "flash", "vibrate"], "default": "flash"},
  {"key": "terminal.shell", "type": "file", "label": "Shell", "kinds": ["program"], "default": "zsh"}
]}

Entry types: bool, number (a range: a slider, or a field), text, choice, colour, file (one of a folder's, or added), action (a button that calls the app). A file entry for a font, a skin or a sound copies what is added into the cartridge, so an export carries it.

Export and import

  • Export... opens squared's file dialog (sq.dialogs, decided 2026-11-25: the person chooses where), in shared storage (FileType::External: the folder sqterm already uses for packages), with <app id>-preferences-<date>.sq to save as, and writes it there.
  • Import... opens the same dialog on .sq files, then Replace or Merge. After an import, every setting is applied again (the generation moves).
  • Until phase 1b writes and reads the cartridge, the app gives the two (Settings::set_transfer); the buttons show when it has.

The file dialog

sq::FileDialog (sq.dialogs, a module of its own, outside import squared;): any app, any screen, a modal pane in the middle (FileDialogPane). Open a file, save one (a name typed, given the ending asked for, and said when it would replace a file), or choose a folder. The app's places as buttons (its files, shared storage, the files it was given, the top), up, the folder's folders then its files by name in any case (hidden names left out unless asked; files by ending), and the choice given to the app through a callback, or an empty path for Cancel.

The UI's zoom

The Stage has it now: zoom(), set_zoom(percent) (50 to 300, steps of 5), pinch_zoom(on), and it keeps the zoom in squared/zoom. For the screen:

  • Least and Most become the Stage's to set, at run time (set_zoom_range(least, most), within least_zoom and most_zoom, which stay the hard limits): a pinch and the slider keep to them.
  • Pinch to zoom is pinch_zoom, made live (today it is set in squared_main only).
  • The zoom itself stays the Stage's (squared/zoom), which a pinch and the slider both keep: a ui.zoom the screen wrote would be left behind by the next pinch, and applied at a start it would undo it (changed 2026-11-25, from "the zoom moves into the preferences"). An export does not carry the zoom until the Stage reads it from the preferences itself.
  • An app that never zooms (a game's canvas) turns the section off.

Done (2026-11-25): set_zoom_range, zoom_least(), zoom_most(), and pinch_zoom at any time (off mid-pinch, the pinch ends with the zoom it reached and its fingers reach nothing until lifted).

3. sqterm and sqIDE

  • What they keep today moves into the cartridge on first start: ~/.config/sqterm/theme.json -> tree/theme.json (and its colours to ui.theme.*), files/terminal.font -> ui.font.*. The old files stay read for one release, then go.
  • sqterm gets the screen as its first screen besides the terminal (its drawer: Settings); sqIDE's left drawer: Settings, on every screen.
  • Their own sections: Terminal (scrollback, bell, the shell), and sqIDE's Workspaces (where they are kept; the default template).

4. Phases

  1. sq.preferences: the cartridge, typed settings, files, export and import (sqdrive vendored); tests on the host, round trip through a .sq.
  2. The Stage: set_zoom_range, a live pinch_zoom. Then sq::SettingsScreen: sections and entries, the invariants, data-declared sections; the keyboard as the wizard's fields have it. First cut (2026-11-25): sq.settings (its own module, outside import squared;): Settings and SettingsScreen (push settings), the app's sections declared in code (SettingEntry::toggle, number, choice, text, action) and squared's Zoom, Input and Preferences (Reset all). Still to come: Appearance, Text and Colours (the Stage switching skins and fonts live first), Export and Import (phase 1b), sections declared as JSON, the colour and file entries.
  3. sqterm and sqIDE: their settings moved in, the screen in their drawers.
  4. sqgui: sections shown and edited in the GUI editor.

Decided (2026-11-25)

  • The zoom, and every other setting, applies live: no restart.
  • A skin of the person's own brings the bitmap fonts it names (its JSON, atlas and fonts are copied into tree/skins/NAME/).
  • An export is dated (<app id>-preferences-YYYY-MM-DD.sq, with -2 and on for a second the same day); none is overwritten.
  • The UI's zoom is in Settings: the zoom, pinch on or off, its least and most.
