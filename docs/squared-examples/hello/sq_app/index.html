sq_app — your code

The user working directory. Everything in it is yours; the generator will not write here again.

sq_app/src/        your sources — every .cpp here is compiled
sq_app/layouts/    your screens, one JSON file each
sq_app/names.json  your model's addresses, when you have a model

Where it starts

src/main.cpp defines squared_main, which the framework calls once, when the first window is up:

void squared_main(sq::App& app)
{
    app.run<Prefs>();                    // your model, on its own thread
    app.stage.push(layouts::landing);    // the first screen
}

import squared;

squared is C++20 modules: a file of yours writes

#include <layouts.hpp>   // what the build makes of layouts/ (a header)

import squared;          // the App, the Stage, widgets, the Telegraph, std

import squared; brings the whole standard library too (C++23's import std;: std::string, std::map, std::print, ...). Only C macros still need an include (assert, errno, va_start, UINT32_MAX: #include <assert.h>, ...), and every #include goes above the imports: a header such as <stdio.h> read after the standard library came in by import is refused. Keep CXXSTD at c++23: a file compiled otherwise cannot read squared's modules. More: squared/docs/programmer/include-layout.md.

Screens are layout files

layouts/landing.json is the screen layouts::landing. The build compiles every file in layouts/ (and names.json) into C++ before your sources, and a mistake in one stops the build with the file and the place: landing.json: rows[1][0].tap: not a tap. The format, every key, and the taps: squared/docs/programmer/layouts.md.

A button's tap is one line:

TapDoes
push settingsthe screen settings, over this one
replace settingsthe screen settings, instead of this one
backback to the screen beneath; at the first screen, leave
quitquit: your model saves and stops
set settings.sound false, do file.open "a.txt"a telegram, to your model

The one rule

No Android headers in this directory.

No <android/...>, no <EGL/...>, no <GLES3/...>. The platform layer in sq_android/ owns all of that and runs your app through sq::App. Keeping Android out of sq_app/ is what lets the same code build under another platform layer, and it is easy to lose one include at a time.

Lifecycle

You write squared_main and your model; the App does the rest:

AndroidWhat happens
the first windowsquared_main, once a process
leaving the screenyour model's background(): save here, it may never come back
coming backyour model's foreground(elapsed)
short of memoryyour model's low_memory()
back at the first screen, or quityour model saves and stops; the app closes

Your model runs on its own thread, so nothing in it blocks the screen. squared/docs/programmer/stage.md has the App and the Stage.
