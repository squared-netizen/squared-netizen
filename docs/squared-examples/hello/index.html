hello

A C++20 Android application built on the Squared framework.

Generated by squared-pg 0.1.0-alpha.1 from template.android.cpp@0.1.0.

Build, package, install

make              # build libhello.so
make apk          # package and sign
make install      # install it (with adb on this phone: no prompt)
make run          # install, then start it (adb)
make logcat       # its log, and Android's crash lines (adb)
make dev          # the build you debug with: CONSOLE=app DEV_LOG=1 install
make console      # a CONSOLE build's Console, here in Termux (no adb);
                  # make dev console: build, install, then connect
                  # in it: ls, pull <path>, push <file>, logcat, libs,
                  # screens (the stack and what each screen keeps),
                  # dump sys (every system command; dump lists the groups)

No Gradle, no Android Studio, no classes.dex, no Java in the build. A compiler, make, and the NDK and SDK command-line pieces. It works on a phone.

make android-status   # what the build found on this host
make android-help     # every target and override

A build prints one short line as each step starts and says the flags once:

hello: flags as before
squared release: flags as before
  sqgen          0 keys, 1 layout; 3 files changed
  cc   sq_app/src/main.cpp
  link libhello.so

When the flags changed (another SQ_MIN_SDK, DEV_LOG=1, CONSOLE=app) it lists every one, a line each, marking what is (new) or (gone), and rebuilds what they affect. Warnings and errors print in full. make V=1 prints every command instead.

adb on the phone itself

Without adb, make install hands the APK to Android's installer, which asks every time, and nothing in Termux can read the app's log (an app reads only its own). With Wireless Debugging (Android 11 and later, on Wi-Fi), Termux's adb reaches the phone it runs on:

pkg install android-tools
make devices                      # what adb reaches, and the steps to connect
adb pair localhost:<pairing port> # once: Settings > Developer options >
                                  # Wireless debugging > Pair device with code
bash tools/device.sh connect      # each time it is turned on (or: connect <port>)
make run                          # install with no prompt, then start it
make logcat                       # the app's lines, a library that failed to
                                  # load, the crash summary
bash tools/device.sh run-as com.example.hello cat files/crash-previous.txt

The pairing dialog closes when you leave it, so keep Termux beside it (split screen or a floating window) while you type the code. Wireless Debugging turns itself off when Wi-Fi does.

make install uses adb only for this phone: the attached device whose build fingerprint matches the one Termux reads, and only when adb's server is already running (it never starts one to look). Anything else, a tablet on USB included, is used only when named: make install DEVICE=<serial>, with the serial make devices shows (SQ_ADB=termux-adb for a USB device reached through termux-adb). run-as needs a debuggable build: DEV_LOG and CONSOLE builds are.

Layout

sq_android/    the platform layer — manifest, resources, entry point
sq_kit/        kit-provided headers (generator-owned)
mk/            generated build fragments (generator-owned)
Makefile       yours; includes the fragments above
.squared/      how this workspace was generated (generator-owned)

sq_android/ is seeded rather than generated on purpose. The manifest, the resources and the platform entry point are all yours to change — that is the expert escape hatch. You should not normally need it, because the defaults work.

Where to start

sq_app/src/main.cpp and sq_app/layouts/landing.json: a screen that says Hello and has a Quit button. squared_main pushes it; the build compiles the layout file into layouts::landing. Add a screen by adding a layout file, a model with app.run<YourModel>(). sq_app/README.md has the rest.

Note what sq_app/ does not include: no <android/...>, no EGL, no GLES. The platform layer runs your app through sq::App; the same code compiles under other templates with a different platform layer. Keeping Android out of sq_app/ is worth defending as you add code.

Rendering

The renderer is chosen when the framework is linked: sq::graphics::Context always exists, and with no GLES backend the null one draws nothing, so this project builds and runs without one — you get a black window and a log line saying so.

With kit.opengl you get sq::gl: EGL context management and GLES 3.0. Shaders are GLSL ES 3.00 (#version 300 es), which needs explicit precision qualifiers in fragment shaders.

make gl-status

Why the SDK version is not in the manifest

AndroidManifest.xml deliberately carries no <uses-sdk>. The levels are passed to aapt2 by the build, so retargeting never means editing a file:

make apk SQ_MIN_SDK=26 SQ_TARGET_SDK=35

SQ_MIN_SDK is more than a manifest entry. The code is compiled for that API level and linked against that level's system libraries from the NDK, so a call to anything newer fails the link instead of the device. The default, 22 (Android 5.1), gives one APK that runs on that and on everything after it. The C++ runtime is linked into your library; the APK carries no libc++_shared.so.

One ABI

This host builds for arm64-v8a. Termux's clang targets aarch64 only, and building four ABIs on a phone is not the use case. A desktop NDK can do more — make android-help explains how.

Independence

This workspace does not depend on squared-pg. The generator is not on the build path, is not referenced by the Makefile, and does not need to be installed to build, run or ship what it produced.
