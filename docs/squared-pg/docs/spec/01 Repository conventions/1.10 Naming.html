1.10 Naming

[!info] Navigation Index: [[Specification Index]] · Parent: [[1 Repository conventions]] Prev: [[1.9 Generated files]] · Next: [[1.11 Dependency direction]]

Purpose

Names must communicate architectural ownership.

Outline

  • ☑ naming conventions per language and resource kind
  • ☑ version identifier rule
  • ☑ machine-path prohibition

Content

Names MUST communicate architectural ownership.

In particular:

  • C++ types use the project's established C++ naming convention.
  • Lua modules use Lua module naming conventions.
  • Resource directories use lowercase, stable identifiers.
  • Version identifiers MUST be explicit where multiple versions may coexist.
  • Files MUST NOT encode transient machine-specific paths.

Related

Resource identifier grammar is a separate concern from file naming and is defined in [[2.8 Templates]] (D-022).
