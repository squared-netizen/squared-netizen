tools/ contains repository-maintenance and developer-facing tooling.

Tools MUST NOT become an undocumented second implementation of generator logic. Generator behaviour belongs in the generator architecture itself.

Scripting language

bash is canonical, and is the only form shipped.

Every script in this repository and in every delivered package is bash. sh is not assumed: bash is a dependency, and one worth having for arrays, set -euo pipefail and process substitution.

The rule began as "bash canonical, fish an optional translation" (D-044), from two bugs shipped in a fish script:

  • $version is read-only in fish, so an assignment silently failed;
  • set --local at top level is invisible inside a function, so a script that reported success removed nothing.

It was tightened to bash-only (D-044 as amended) after a third: an installer's argument loop rejected every valid path. The common factor is not that fish is a poor language. It is that the fish scripts were written where no fish interpreter existed, so every one of them shipped untested alongside bash that had been run.

An untested translation delivered beside a tested original is worse than no translation. It carries the authority of the thing next to it and none of the evidence.

A fish translation MAY exist if someone maintains it against a working install.sh and runs it. It is not generated, and it is not shipped by default.
