AUD-B-001 — §2.7.12 restates the boundary guarantee whose home is §2.12

Status: requires decision · Severity: serious

File: 02 Generator architecture/2.7 Project generation model.md Heading: 2.7.12 Ownership transition

Correction: delete ### Independence and ### Leakage prohibition from 2.7.12 (keep the ownership-transfer mechanism) and leave the guarantee in §2.12 only, cited via the existing link. Confirm no distinct requirement is lost in the deletions (compare against AUD-A-001).

F — Normative language

Status: awaiting decision · Severity: serious

No vault note contains an RFC 2119 conformance clause: the normative meaning of MUST/SHOULD/MAY, what reading rules the reader applies (e.g. RFC 2119's "implementation may ignore a SHOULD only with justification"), and the hard-vs-soft split for the keyword set. Spec conventions uses the capitals and the determinism table but nowhere states the standard-reading clause.

Correction: add the clause as §0 (e.g. in Spec conventions, or the vault-level entry note) in the form the follow-up pass already anticipates.

AUD-F-002 — keyword choices: internally consistent

The MUST/SHOULD census and a contradiction sweep over the requirement pairs found no property stated as MUST in one note and SHOULD in another, and no contradicting MAY/MUST pair. No lowercase "must"/"should" reads as an unmarked requirement (2.15.7's "should therefore" is prose). One item is deferred to a decision (AUD-F-003).
