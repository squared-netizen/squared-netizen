sqedit

A text tool built on parsing expression grammars, in the spirit of LPeg, to replace sed and grep in scripts: readable patterns, literals with no escaping, and a count that is checked rather than hoped for. Part of the squared SDK.

Jobsed or grepsqedit
Take a fieldsed -n 's/^libc++: //p' PINNEDsqedit pick '"libc++: " {.*}' PINNED
A field from JSONsed -n 's/^ "version": "\([^"]*\)".*/\1/p'sqedit json version manifest.json
Print linessed -n '2,29p' "$0"sqedit lines 2..29 "$0"
Lines to a patternsed -n '2,/^set -euo/p'sqedit lines '2.."set -euo"' "$0"
Change a linesed -i 's\|id = gethostid ();\|id = 0;\|' f; grep -q 'id = 0;' fsqedit sub --in-place --expect 1 '"id = gethostid ();"' 'id = 0;' f
Literal, no pattern(escape by hand)sqedit sub -F --in-place --expect 1 'execve("/bin/sh", ' 'execve("/system/bin/sh", ' f
Wrap a linesed -i '/^ if (setgid/{i\ ... n;a\ ...}' fsqedit wrap --in-place --expect 1 --lines 2 '" if (setgid(getgid()) != 0)"' '#if !defined(__ANDROID__)' '#endif' f
Find linesgrep -E, grep -q, grep -csqedit match '"class " %w+' f (-o -c -q -v -x -n)

--expect N makes a command that changes a file fail, with nothing written, when the file holds a different number of matches than the script assumes. Exit status as grep's: 0 matched (or changed as expected), 1 no match or a count other than --expect, 2 a usage, pattern or file error, reported with where it is (sqedit: pattern:1:14: expected a closing quote).

Patterns

Parsing expression grammars, written as LPeg's re module writes them. A literal is quoted text and means only itself; everything unquoted is pattern.

WriteMatches
"text" or 'text'exactly that text
.any one character (a UTF-8 code point, not a byte)
[a-z_], [^"]one character in, or not in, a set
p qp, then q
p / qp; if p fails, q (ordered: the first that matches wins)
p*, p+, p?repetition, greedy and possessive (no backtracking into it)
&p, !pp must, or must not, follow; nothing is consumed
{p}capture what p matched
{:name: p :}a named capture
{~ p ~}a substitution capture: the match, with the parts inside marked -> 'new' replaced
name <- pa rule; rules make a grammar, and may call each other and themselves
%nl, %s, %d, %wnewline, space, digit, alphanumeric (and %a %l %u %x %p %c %g; %S and the like, their complements)

A match is anchored where it starts, as in every PEG; the commands search for the first place a pattern matches, line by line or, with --whole, across the file; with -x (match, pick, sub) the pattern must match the whole line, as with grep -x. In sub's replacement, {name} is a named capture, {1} the first capture, {0} the whole match, and \n, \t and \\ a newline, a tab and a backslash: one line can become two.

-g file.peg makes a file's rules usable by name in a pattern. sqedit ships json (a string and a number), c (a string literal, a comment, an include) and ini (a key: value line): -g json. JSON in a JSON file is sqedit json's job, not a grammar's.

Build

CXX=/path/to/clang++ sqmake test

clang and libc++ 19 or later (23 is what sqterm and CI use), C++23 with import std;. Offline, and with no sed, grep or awk anywhere in the build: sqedit is built before anything uses it. The matching is a library (sqedit.peg, build/libsqedit.a); the command is a thin front end to it.

The design, decided 2026-11-18, is in "sqedit: design".
