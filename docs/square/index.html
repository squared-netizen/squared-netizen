square

The workspace manager of the squared SDK, and the one tool that knows what a workspace is. sqpg creates a workspace once; from then on square answers every question about it and makes every change to its shape.

Status: specified, not yet built. docs/spec.md, draft 0.1 (2026-11-20).

What it will do

  • Answer questions, in JSON. square info, square where <role> (the app, its layouts, its docs), square owner <path>, square verify, square explain <shim> for sqgui: the SDK's tool protocol (square call, square describe), and the same in process through libsquare. No daemon.
  • Keep a workspace's record. A workspace is an exploded cartridge (SQ-INF/manifest.json, kind workspace): its template, kits and packages, each path's role and ownership. People write Lua (build.lua); square writes the JSON.
  • Leave the build to the workspace. A template's and a kit's build conventions are Lua files in the workspace (sq/build/*.lua) that build.lua includes, so sqmake builds it asking square nothing.
  • Ask sqcart, never read manifests itself. Every manifest is defined by the Squared Cartridge Specification; square reads the sections addressed to it through sqcart, so a change in the format touches sqcart and square alone.
  • Change a workspace safely. Adding a kit or a package and updating a resource run as plan, decide, apply: a plan the developer reads, an answer for every conflict, and a journalled transaction that a crash cannot leave half done. Ownership classes decide the rest: a seeded or user file is never touched.
  • Extract. Turn a workspace that has grown to suit its developer into a template, kits or packages for the next project, through a plan file the developer edits.

Where it sits
