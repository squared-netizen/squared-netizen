Repositorysquared-netizen/squared-pg

squared-pg is an offline-first project generator for applications built on the squared framework. A native C++20 engine provides the generation capability and a Lua 5.4 control layer sequences it into workflows; the output is a self-contained workspace the developer owns outright.[1]

Overview

The engine is a programmable pipeline: it knows what a template, a kit, a package and an asset are, and how to resolve, validate and materialise them, but it does not decide which ones are wanted. Lua does: it parses arguments, loads configuration, chooses the template and kits, and calls engine operations in whatever order a workflow needs, so workflows can change after release without a rebuild.[1] The command-line tool sqpg is one consumer of that stack. A bootstrap script clones squared and sqcart beside it, and sqpg initialize lays out an environment of a version-controlled project tree, a sandbox and the tools.[1]

Concept

A request becomes a workspace: Lua chooses, the engine resolves and writes.

Architecture

Engine

A C++20 engine with a lifecycle state machine and a set of core services, exposed as an enumerable set of operations; its public headers are under engine/include, and a binding layer under engine/lua keeps the C++ and Lua boundary narrow.[1][3]

Workflows

Lua 5.4 modules in lua/ sequence the engine's operations: list, new, plan and initialize are workflows, not fixed code paths.[1]

Resources

Templates, kits, packages and assets are inert data under resources/; the squared package repository and sqcart are brought in beside it.[1]

In the SDK

sqpg is the tool that creates: it sets up a workspace tree and generates a project from a template, kits and packages, and it is installed in bin like any other tool. Managing the workspace afterwards is square's job: every question about a manifest goes to square, which asks sqcart. Building is sqmake's. See the squared SDK.

Building (planned)

Generated projects build with make today. The plan is for the build step to go through sqmake, a separate library and command line that runs the build itself from a short Lua build file, with no generated make, CMake or Ninja files; it knows how to build, not what a workspace is.

Specification

A functional specification, kept as an Obsidian vault with a decision log and open questions, guides the design; during the initial implementation the repository is the ground truth and the specification is amended to match.[3]

Features

  • Generates terminal and Android applications from templates, with kits that add capabilities such as OpenGL or a Lua workspace.[1]
  • sqpg plan shows what a generation would do without doing it.[1]
  • Builds and runs with a C++20 compiler and make alone; CMake is optional.[2]
  • No network at build or run time.[1]
  • Workflows editable after release, without rebuilding the engine.[1]
  • Tools that keep squared's templates and a generated project in step (template drift checks, porting back to the template).[5]

Use cases

  • sqpg new hello --template template.terminal.cpp --kit kit.terminal, then make: a terminal program.[1]
  • An Android app on a phone with no Gradle: --template template.android.cpp --platform android, then make apk.[1]
  • Adding a Lua script workspace beside the C++ one with --kit kit.lua.[1]
