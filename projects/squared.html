Repositorysquared-netizen/squared

squared is a cross-platform software development kit for Linux and Android, written in C++23 as named modules, with a Lua 5.4 scripting layer, for games, simulation software and tooling.[2] It is undergoing a ground-up rewrite, and its APIs are not yet stable.[1]

Overview

squared is published as a package repository: its framework lives under packages/package.squared-core and its application templates under templates/, and its one consumer is the squared-pg project generator, which copies them into a workspace the developer owns.[1] Code is written against import squared; or a single module such as import sq.gui;.[2] An application is split into a model, running on its own thread, and a Stage of screens and panes on the UI thread; the two exchange messages and snapshots through a Telegraph.[3] On Android the platform layer is a NativeActivity with no Java of its own, and the APK is built with make, without Gradle.[4]

Concept

An application on squared: the platform starts it, the Stage draws it, the model runs apart from it.

Architecture

Modules

One named module per directory: app, assets, console, data, dev, files, font, gles, graphics, gui, math, messaging, stage, term and time, each built from a partition per everyday type, with implementation units and tests beside it.[2] The standard library comes in as import std, from libc++'s module sources pinned in third_party/libcxx.[2]

Application model

The App holds the Telegraph, with the model at its far end and the Stage at its near end; there is one App for the process.[3] The model runs on its own thread and publishes snapshots; the Stage, on the UI thread, owns screens, panes and widgets, and the platform delivers input and the window to it.[3]

Platform

The Android template is a NativeActivity in C++ with no classes.dex unless asked for: running in the background adds a tiny generated dex (tools/dexgen) for a foreground service.[4] Desktop Linux runs the same application code.[2]

Build

make and clang with libc++. Module interfaces and objects go through a build cache keyed by what they read, shared between workspaces.[5]

Features

  • C++23 named modules throughout, with import std.[2]
  • Android apps with no Java, no Gradle and no Android Studio, built and installed from a phone.[4]
  • A model on its own thread, a UI on another, and a message line between them (the Telegraph).[3]
  • A GUI of screens, panes and widgets, with pinch zoom for every app, kept across launches.[5]
  • Text through FreeType: font sets with system fallbacks and a glyph atlas.[5]
  • A terminal core (sq::term): an ECMA-48 parser, a cell grid with scrollback, and a pty.[5]
  • Running in the background on Android: a foreground service with a notification and an optional wake lock.[5]
  • A development Console reachable from Termux, and log lines sent over UDP in development builds.[4]

Use cases

  • Writing an Android app entirely on a phone, from generation to install.
  • A terminal emulator: sqterm is written on squared.
  • Games and simulations that keep their model apart from their UI.
  • Tools for Linux that share code with an Android app.
