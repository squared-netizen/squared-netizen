sqcart is the reference implementation of the Squared Cartridge Specification 2.0, the .sq container format used for squared's templates, kits, packages, asset bundles, plugins and distributable applications. It is standalone C++20, with no dependency on squared-pg or on the squared framework.[1]

Overview

A cartridge carries a manifest, SQ-INF/manifest.json, with a fixed envelope common to every kind (format, version, kind, id, version, licence) and the payload that kind describes.[3] The kind is an opaque token rather than a closed set, and the role of a file is never inferred from its name: there is a single .sq extension.[3] The library is split so a runtime or an Android launcher links the reader alone, carrying no compressor, canonical-ordering logic or manifest writer.[1] The longer aim is high-capacity, high-performance containers that hold both very large datasets and executable extensions.[1]

Concept

Written once by a packaging tool, read by the generator or by a runtime that carries only the reader.

Architecture

Targets

sqcart::read (always built), sqcart::write (packaging tools), a sqcart command-line tool for people and CI, and a deferred Lua binding.[1]

Manifest

The envelope is common to every kind and versioned; a reader refuses a format version it does not know, in either direction.[3]

Embedding

A host can supply its own miniz and yyjson (SQCART_USE_EXTERNAL_MINIZ, SQCART_USE_EXTERNAL_YYJSON) and link the reader into its own target.[1]

Features

  • One container format for templates, kits, packages, asset bundles, plugins and applications.[1]
  • A read-only library small enough for a runtime.[1]
  • Builds with CMake or, on Termux, with make check.[1]
  • Offline by construction: no network resolution of any kind in the format.[3]

Use cases

  • squared-pg reading templates and kits as cartridges.
  • Shipping an asset bundle or plugin that a squared app opens read-only.
  • sqterm's packages reuse the cartridge manifest envelope (kind package) for pkg.[4]
