sqmake is the build system of the squared SDK. It keeps make's model (targets, prerequisites, rebuild when what a target is made from changes) and drops make's syntax; it runs the build itself and never writes make, CMake or Ninja files for another tool to run.[3] It builds a workspace without knowing what one is: it asks square what to build.[1]

Overview

A target is rebuilt when an input is newer, when its command's hash changed, when a header its compile read changed, when a module it imports was rebuilt, or when the toolchain changed: the toolchain's fingerprint, a hash of the compiler's version, the C++ library's version, the target and every flag that changes a compiled module, is part of every command's hash.[3] Commands are argument lists run without a shell, and sqmake build --explain prints the whole resolved graph and every command.[3] One toolchain builds every C++ module in the SDK, so a compiled module never meets one made by another compiler.[4]

Concept

square says what to build; sqmake plans it with the SDK's one toolchain and runs what is stale.

Architecture

Stages

Load (Lua registers toolchains, rules and targets), Resolve (conventions and usage requirements), Plan (a graph, module dependencies included; a cycle is refused), Check (what is out of date), Run (a thread pool).[3]

Modules

clang-scan-deps orders the compiles; compiled modules are outputs in the graph, kept in a folder named by the toolchain's fingerprint, with one std module per fingerprint; a library written as modules is built from its sources by its consumer.[3]

Toolchain

Defined once, in squared (build/toolchain.sh): the flags that change a compiled module are the toolchain's, never a target's, and a target asking for another is refused with a plain message.[3][4]

Lua

Standalone, sqmake owns its Lua state; embedded (in sqpg), it uses the host's, in its own sqmake table, and build files run sandboxed.[3]

In the SDK

sqpg creates a workspace, square manages it, and sqmake builds it. See the squared SDK.

Features

  • make's model without make's syntax: named inputs and outputs, explicit rules, ordinary Lua functions.[3]
  • Rebuilds on command and toolchain changes as well as file times, and on headers the compiler reports.[3]
  • C++23 modules ordered by clang-scan-deps, from sqterm's llvm package.[3]
  • Offline, no daemon, one small binary; it runs on the phone in sqterm.[3]

Use cases

  • Building a workspace sqpg created, from the inputs square names.
  • An IDE or tool embedding libsqmake to build and to show the graph.
  • Building squared and the kits with the same toolchain as applications (an open question).[3]
